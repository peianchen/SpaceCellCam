# 程式版本與實驗資料管理

更新：2026-11-14。此專案以 **程式、流程及可重現設定範例**為 Git 保存範圍。
本次整理保留原有路徑；忽略檔案仍留在本機，沒有因整理而刪除。

## 保存在哪裡

| 類別 | Git | 本機／獨立資料備份 |
|---|---|---|
| 相機韌體、PlatformIO 設定、既有程式庫與授權 | 納入 | 原樣保留 |
| V2、影片工具、AI pilot、歷史程式及測試 | 納入 | 原樣保留 |
| 操作、方法限制、開發文件與小型範例 | 納入 | 原樣保留 |
| `user_config.example.py`、`pilot_config.example.json`、`videos_template.csv` | 納入 | 複製後編輯成本機設定 |
| `user_config.py`、`ui_settings.json`、`pilot_config.json`、`videos.csv` | 排除 | 保留並另行備份 |
| 原始照片／影片、實驗標註、AI dataset 清單及預覽 | 排除 | 保存原始資料、hash、來源與標註版本 |
| `runs/`、results、參數掃描、診斷圖及 CSV 結果 | 排除 | 與該次實驗設定、commit 一起保存 |
| 模型 checkpoint、虛擬環境、build/dist、快取、簡報生成物 | 排除 | 需要時另存；可重建者由程式重建 |

Git 推送成功不代表原始資料或結果已完成備份。資料位置可在實驗紀錄中記錄；不要把完整研究清單或憑證混入公開程式文件。既有 `lib/SdFat` 的文件壓縮包、工具及範例是原先追蹤的第三方程式庫內容，不當成大型實驗資料移除。

## 每次實驗建議留下的紀錄

- 實驗 ID、物種確認狀態、獨立培養／樣本 ID、條件與日期。
- 原始資料位置、檔案數／缺幀、輸入檔 hash、真實取像間隔及尺度校正。
- 影片製作時的排序、範圍、尺寸、裁切及 FPS；原圖保持不變。
- `git rev-parse HEAD` 的提交編號、完整執行設定、套件版本、run manifest、日誌與輸出。
- 標註者、確認時間、原圖與 mask hash、資料角色及版本；草稿與確認狀態分開。

當前程式不會自動完整收集以上所有資訊，需以實驗紀錄補足，不能把此建議當成已實作功能。

## 開發與推送順序

在 SpaceCellCam 根目錄：

```powershell
git fetch origin
git status --short --branch
git log --oneline --left-right HEAD...origin/main
git diff --stat
```

先確認遠端差異，再選擇性加入已審查的程式與文件；不要直接強制推送。待提交清單逐檔檢查大小、資料種類與本機設定。新增檔案超過 1 MB 應另行檢查原因；大型影片／模型不要因體積尚未達 GitHub 限制就提交。

既有 .gitignore 會排除常見結果位置，不能涵蓋所有自訂目錄。原始資料與結果最好放在儲存庫以外；若新增專案內輸出位置，先增加精確的排除規則。已追蹤檔案不會被新的 .gitignore 自動排除。

未來若要刪除資料、改動公開範圍、搬移資料庫或重新組織歷史版本，需另訂範圍；本次整理沒有進行這些操作。
